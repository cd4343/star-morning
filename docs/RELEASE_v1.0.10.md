# Release v1.0.10

发布日期：2026-05-14

## 本次目标

完成手机号验证码登录的可测试 MVP，为后续真实短信服务商和手机一键登录打基础，同时不影响当前线上“手机号 + 密码”登录。

## 已完成

- 新增 `auth_sms_codes` 数据表，用于保存验证码哈希、用途、过期时间、尝试次数和消费状态。
- 新增 `POST /api/auth/sms/send`：发送登录验证码。开发环境使用 mock provider；生产环境未配置短信服务商时返回 503。
- 新增 `POST /api/auth/sms/login`：使用 6 位验证码登录并签发 JWT。
- 新增 `POST /api/auth/mobile/one-click-login` 占位接口，等待真实服务商 SDK 和 token 校验接入。
- 登录页新增“密码登录 / 验证码登录”切换。
- 原密码登录继续保留，并兼容历史 `users.email` 与新增 `users.phone` 字段。

## 上线影响

- 不需要替换服务器数据库。
- 后端启动会自动创建 `auth_sms_codes` 表和相关索引。
- 未配置真实短信服务商时，线上验证码登录不可用，但密码登录不受影响。
- 开启真实短信前需要配置服务商密钥、短信签名、模板 ID，并在后端补充 provider 实现。

## 回归重点

- 手机号密码登录。
- 验证码发送接口在开发环境返回测试验证码。
- 验证码错误、过期、重复使用、尝试次数超限。
- 验证码登录后进入家庭成员选择页。
- 未配置短信服务商的生产环境返回清晰错误，不影响密码登录。
