# v1.1.3 上传服务器前检查记录

检查日期：2026-05-18

## 本版重点

- 孩子端主入口收敛为挑战、早餐、奖励、我的，移除星图和早晨流程入口。
- 早餐改为按日期制定，孩子端按主食、饮品、水果、蛋白、套餐等分类组合选择。
- 任务完成后支持即时宝箱反馈，宝箱预览使用中英文稀有度说明。
- 学习、生活、运动、活动、情绪等任务分类和奖励结算规则已进一步拆分。
- 游戏票保留为每日基础时长 + 学习任务节省时间 + 家长手动补发的模型。
- 备份脚本改为 SQLite 一致性快照：优先 `VACUUM INTO`，失败后 checkpoint 再复制。

## 数据与备份

- 上传前本地数据库快照：`backups/stellar-pre-upload-20260518-105400.db`。
- 本地数据库存在 1 条历史孤儿任务记录：`task_entries` rowid `19` 引用的孩子用户已不存在。
- 该孤儿记录不影响代码构建和接口 smoke test，但如果要直接上传本地 `stellar.db` 到服务器，建议先确认是否删除这条历史测试记录。
- 如果服务器已有正式数据，建议只上传代码并让后端迁移补齐字段；不要直接用本地库覆盖服务器库。

## 代码健康结论

- 当前版本可以作为上传服务器候选版。
- 短期风险主要在本地测试库的历史孤儿数据，不是代码兼容性问题。
- 后端 `server.ts` 仍然较大，后续继续开发时建议按业务域逐步拆成路由模块，避免新功能继续堆到单文件。
- 前端若继续增加功能，建议优先抽取任务卡片、奖励卡片、筛选栏、统计面板等复用组件，降低页面级文件体积。

## 上线建议

1. 服务器先备份现有数据库。
2. 上传代码后分别执行前后端依赖安装与构建。
3. 配置生产环境变量：`JWT_SECRET`、`STARCOIN_DB_PATH`、`ENABLE_DB_BACKUP=true`、`STARCOIN_BACKUP_DIR`。
4. 启动后先检查 `/api/health`，再用一个家长和一个孩子账号跑登录、任务完成、早餐选择、奖励页、我的页。
5. 上线后执行一次 SQLite `PRAGMA foreign_key_check`，确认服务器正式库没有历史孤儿数据。
