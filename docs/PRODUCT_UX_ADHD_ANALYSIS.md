# Star Coin 产品逻辑与 ADHD 友好化分析

## 项目设计框架

Star Coin 的核心不是单纯的任务清单，而是一个家庭内的行为激励系统。它把孩子的日常任务拆成可完成的短周期行为，再通过金币、经验、特权点、宝箱、抽奖、成就和家长审核，把“完成任务”转化成看得见的成长反馈。

整体逻辑可以理解为：

1. 家长制定规则：任务、奖励、惩罚、商品、特权、成就。
2. 孩子执行任务：查看任务、启动计时、提交完成。
3. 系统即时反馈：计时、完成提示、可能触发宝箱、进入待审核。
4. 家长审核评价：奖励金币/经验/特权点，也可执行惩罚。
5. 孩子消费奖励：商城、储蓄、抽奖、特权兑换、背包兑现。
6. 长期成长反馈：等级、成就、连续记录、惩罚记录、家庭统计。

这个设计想解决的问题是：把抽象的自律、时间观念和家庭规则，变成孩子能感知、能参与、能期待的反馈循环。

## 当前前端功能框架

### 认证与家庭

- 注册、登录、创建家庭。
- 选择家庭成员。
- 孩子端通过 PIN 切换到家长端。
- 家长管理家庭成员和 PIN。

### 家长端

- 仪表盘：待审核任务、审核历史、家庭统计。
- 任务管理：普通任务、并行任务、时间窗口、家庭任务。
- 心愿管理：商城、储蓄、抽奖、宝箱奖励池和宝箱设置。
- 特权管理：用特权点兑换的特殊权益。
- 成就管理：任务数、金币数、连续天数等成就规则。
- 惩罚管理：惩罚等级、扣除规则、负余额保护、记录统计。

### 孩子端

- 任务页：今日/本周任务、计时、暂停、完成、并行任务浮层。
- 心愿页：商城兑换、储蓄、抽奖、背包、特权兑换、物品转赠。
- 我的页面：等级、成就、惩罚记录、宝箱记录。

## 当前后端功能框架

### 主要 API 模块

- 认证：登录、注册、找回密码、家庭创建、成员切换。
- 家长任务：任务 CRUD、家庭任务 CRUD、审核、审核历史。
- 孩子任务：任务列表、任务提交、重复提交限制。
- 奖励：金币、经验、奖励经验、特权点、成就检查。
- 惩罚：设置、执行、动态调整、记录、孩子未读通知。
- 心愿：商城、储蓄、抽奖、背包、兑现、撤销、转赠。
- 宝箱：奖励池 CRUD、设置保存、孩子宝箱记录查询。
- 特权：特权 CRUD、兑换。
- 统计：家长仪表盘、金币收支、惩罚统计、孩子个人页数据。

## 用户体验欠缺

### 孩子端

1. 奖励闭环不够即时  
   任务完成后通常进入待审核，孩子需要等待家长确认。对低龄或 ADHD 孩子来说，延迟反馈会削弱“我刚刚完成了”的获得感。

2. 计时体验还不够稳定  
   并行计时条固定在底部，不可移动；大计时弹窗总是全屏居中。多任务时可能遮挡内容，也缺少“我正在做哪一个”的强提醒。

3. 任务拆分能力不足  
   当前任务更像单个条目，没有内置“步骤 1/2/3”或“先做 5 分钟”的微任务结构。对 ADHD 孩子来说，任务越大，启动成本越高。

4. 时间感知还偏数字化  
   主要是倒计时数字。数字倒计时对部分孩子不够直观，建议加入颜色、进度环、沙漏/区段视觉、临近结束的柔和提示。

5. 失败和超时的情绪保护不足  
   超时目前是状态和审核依据，但还可以增加“补救路径”：延长 3 分钟、拆成小步继续、提交部分完成，减少挫败感。

### 家长端

1. 规则说明不够集中  
   奖励、惩罚、宝箱、抽奖、商品定价分散在不同页面和代码中，家长不容易建立稳定规则。

2. 审核负担偏重  
   家长需要逐条审核、评分、选择惩罚。若任务很多，审核变成新的负担，反馈也会延迟。

3. 设置和实际逻辑存在未闭环  
   宝箱设置已能保存，但后端触发逻辑尚未使用这些设置，容易让家长产生“我设置了但没效果”的不信任感。

4. 缺少家庭规则引导  
   当前能配置很多内容，但缺少“按年龄/任务难度/ADHD 支持模式”的默认方案。

## ADHD 友好化方向

以下建议是产品设计建议，不替代医学诊断或治疗。ADHD 孩子的差异很大，最好让家长可以按孩子实际情况开关和调节。

### 1. 缩短奖励延迟

- 任务提交后立即给“临时星光”或“待确认奖励”，家长审核后再转正。
- 宝箱可以在提交时立即打开，但奖励标记为“待家长确认”。
- 对低风险任务支持自动通过，例如喝水、整理书包、阅读 10 分钟。
- 增加“即时鼓励语”：不是只说等待审核，而是明确告诉孩子“你已经完成第一步，奖励正在等待确认”。

### 2. 增强时间观念

- 倒计时使用进度环、颜色区段和剩余阶段，而不是只显示数字。
- 把时间拆成短段：5 分钟启动、10 分钟专注、休息 2 分钟。
- 增加“开始前准备”步骤：我要做什么、需要什么、完成标准是什么。
- 结束前给柔和提醒：还剩 5 分钟、2 分钟、30 秒。
- 超时后显示“继续完成”而不是单纯失败。

### 3. 降低启动难度

- 任务支持子步骤，例如“整理书包”拆成：清空、放课本、放文具、检查。
- 给每个任务一个“第一步按钮”：只要求孩子先开始最小动作。
- 允许家长设置任务难度和预计阻力，系统自动建议奖励。
- 对长期任务提供“今天只做一点点”的进度记录。

### 4. 增强获得感

- 完成任务后立即出现清晰动画、音效和完成徽章。
- 把金币、经验、特权点分开解释：金币用于小奖励，特权点用于重要权利，经验代表成长。
- 显示“离下一个目标还差多少”，但不要制造压力。
- 增加连续努力保护：即使某天失败，也可以用补救任务保住连续记录。

### 5. 减少不确定性

- 每个任务卡片显示明确结果：完成后预计得到多少，是否需要审核，多久内审核。
- 宝箱概率要可解释：简单任务多少概率，中等多少，困难多少，保底几次。
- 抽奖和宝箱避免过度随机，给孩子可预测路径，例如“完成 3 个任务必得一次小宝箱”。
- 家长端提供“规则预览”：今天孩子最多能获得多少金币、多少特权点。

### 6. 支持自律而不是只靠奖惩

- 增加复盘：今天我完成了什么、哪里卡住了、下次第一步是什么。
- 惩罚尽量从“扣除”转为“修复任务”：补做、整理、道歉、重新规划。
- 家长端展示趋势：哪些任务总超时，可能说明任务过大或规则不清晰。
- 对高频失败任务给家长建议：降低难度、拆分步骤、换时间段、减少并行。

## 建议新增模式

### ADHD 支持模式

打开后默认启用：

- 短任务优先展示。
- 任务卡片只突出一个主按钮。
- 倒计时大视觉化。
- 提交后立即给临时奖励反馈。
- 超时显示补救选项。
- 并行任务数量默认限制为 2 个。
- 宝箱采用低随机、高保底规则。

### 家长低负担模式

- 小任务自动通过。
- 每日固定审核时间提醒。
- 批量审核但保留异常任务单独处理。
- 自动生成奖励建议和任务调整建议。

### 规则透明模式

- 每个奖励系统都有说明：为什么得到、什么时候到账、能换什么。
- 每个惩罚都有修复路径：如何补救、如何恢复。
- 每个商品/特权有定价建议：轻量奖励、周奖励、长期目标。

## 优先级建议

1. 修复宝箱设置后端闭环，避免家长设置失效。
2. 增加孩子任务完成后的即时反馈和待确认奖励。
3. 优化计时器位置、拖动、避让和视觉时间感。
4. 补充任务子步骤和微任务启动按钮。
5. 补完整规则与经济系统文档。
6. 建立端到端测试数据和回归脚本。
