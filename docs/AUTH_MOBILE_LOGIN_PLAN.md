# 手机账号与一键登录设计规划

最后更新：2026-05-14

## v1.0.10 已落地范围

- 后端已新增 `auth_sms_codes` 表，验证码只保存哈希值，默认 5 分钟过期，最多尝试 5 次。
- 后端已新增 `POST /api/auth/sms/send` 与 `POST /api/auth/sms/login`。
- 前端登录页已支持“密码登录 / 验证码登录”切换。
- 开发环境默认使用 mock 短信通道，接口会返回 `devCode` 方便本地测试。
- 生产环境未配置真实短信服务商时，接口返回 503，不会误导用户认为短信已经发出。
- `POST /api/auth/mobile/one-click-login` 已保留接口入口，但真实一键登录仍需服务商 SDK 与后端 token 校验。

## 1. 当前状态

项目当前已经使用“手机号 + 密码”作为家长账号登录方式，但历史字段名仍为 `users.email`。前端注册页有短信验证码交互，目前验证码仍是本地模拟，不是真实短信服务。

v1.0.10 已完成验证码登录 MVP 和数据表落地；真实短信服务商与运营商一键登录仍不直接接入，避免在缺少密钥与灰度方案时影响线上登录稳定性。

## 2. 目标登录方式

### 第一阶段：手机号 + 密码

- 保留当前登录方式。
- 登录时继续使用手机号和密码。
- 后端增加 `users.phone` 字段，逐步从 `email` 字段迁移到明确手机号字段。

### 第二阶段：手机号 + 短信验证码登录

- 家长输入手机号。
- 后端生成验证码并通过短信服务商发送。
- 验证码只保存哈希值，不保存明文。
- 验证通过后签发 JWT。
- 注册、登录、找回密码都可以复用短信验证码能力。

### 第三阶段：手机一键登录

一键登录通常依赖手机运营商或第三方聚合 SDK。建议做成 provider 抽象：

- `sms`: 短信验证码。
- `carrier`: 运营商一键登录。
- `wechat`: 微信授权登录，后续可选。
- `apple`: Apple 登录，后续可选。

前端只调用统一接口，后端根据 provider 校验 token。

## 3. 建议后端接口

```text
POST /api/auth/sms/send
POST /api/auth/sms/login
POST /api/auth/mobile/one-click-login
POST /api/auth/mobile/bind
POST /api/auth/mobile/unbind
GET  /api/auth/mobile/status
```

## 4. 建议数据结构

已预留：

- `users.phone`
- `users.phoneVerifiedAt`
- `users.authProvider`
- `users.oneClickProvider`

后续建议新增：

- `auth_sms_codes`：验证码哈希、过期时间、尝试次数、用途。
- `auth_login_events`：登录方式、IP、设备、成功/失败原因。
- `auth_identities`：第三方身份绑定，例如运营商 token、微信 openId。

## 5. 安全规则

- 验证码 5 分钟过期。
- 同一手机号 60 秒内只能发送一次。
- 同一手机号 15 分钟内最多 5 次。
- 同一 IP 15 分钟内最多 30 次。
- 验证码最多尝试 5 次，超过后失效。
- 日志中手机号必须脱敏。
- 一键登录 token 只能由后端向服务商验证，前端不能直接信任手机号。
- 绑定/解绑手机号需要当前登录态和二次确认。

## 6. 测试清单

### 手机号密码登录

- 正确手机号和密码能登录。
- 错误密码返回明确提示。
- 未注册手机号提示注册。
- `last_phone` 只保存手机号，不保存密码。

### 短信验证码

- 手机号格式错误不能发送。
- 60 秒倒计时期间不能重复发送。
- 过期验证码不可用。
- 错误验证码次数超限后不可继续尝试。
- 验证码登录后能进入家庭选择。

### 一键登录

- provider token 有效时能登录。
- provider token 无效时拒绝。
- 未绑定手机号时进入绑定/注册流程。
- 已绑定手机号时直接进入选择家庭成员。
- 切换设备后仍可登录。

### 风险回归

- 原手机号密码登录不受影响。
- 孩子/家长角色切换不受影响。
- 找回密码不受影响。
- 服务器未配置短信服务商时，不显示真实短信发送成功。

## 7. 上线策略

1. 先上线字段预留和文档，不改变登录行为。
2. 增加真实短信服务的后端接口，前端仍保留密码登录。
3. 开启短信登录灰度开关。
4. 再接入一键登录 SDK，并以配置开关控制。
