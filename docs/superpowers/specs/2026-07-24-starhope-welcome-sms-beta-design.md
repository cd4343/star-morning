# Phase 14：星希望欢迎页、真实短信注册与百人内测设计规格

**状态：** 已按 2026-07-24 用户确认的方案 A 锁定，等待书面复核
**范围：** 对外品牌文案、首次欢迎页、阿里云短信认证、约 100 人内测容量验证、生产部署与回滚
**边界：** 不开发邀请码系统，不替换 `stellar.db`，不全量重命名项目目录、域名、数据库、API 或部署脚本

## 1. 目标与成功标准

本阶段让受邀朋友直接访问 `http://starcoin.h5-online.com/`，经现有 301 跳转进入 HTTPS，在手机上看到“星希望”欢迎页，并可使用中国大陆手机号接收真实验证码完成注册或登录。

成功标准：

1. 首次访问的未登录用户看到移动端欢迎页；按钮立即可点，没有强制倒计时。
2. 已登录用户访问根路径时直接进入现有家庭选择流程，不出现欢迎页。
3. 用户选择“开始使用”或“已有账号”后，本机后续访问根路径恢复现有智能分流，不重复制造登录阻力。
4. 所有主要用户可见品牌文案统一为“星希望”；内部技术标识保持兼容。
5. 生产环境使用阿里云号码认证服务的 `SendSmsVerifyCode` 与 `CheckSmsVerifyCode`，验证码不由前端生成或校验。
6. 100 个注册账号、20 个并发混合操作的容量验证中无 `SQLITE_BUSY`、无数据错写、无进程崩溃，非短信业务请求错误率为 0。
7. 生成一个最新累计 code-only 增量包，服务器只需上传并部署该包；包内不含数据库、密钥、环境文件、上传内容或历史临时包。

## 2. 欢迎页交互

### 2.1 停留时间

欢迎页不是必须看完的开屏广告，因此不设置自动倒计时或强制停留：

- 页面完成首屏渲染后，两个操作立即可用。
- 新用户通常会自然停留约 3–5 秒阅读；熟悉用户约 1 秒即可继续。
- 不自动跳页，避免慢速读者、网络较慢设备和无障碍用户被强制打断。
- 若未来必须改为纯开屏动画，最长使用 1.8 秒并保留立即跳过；本阶段不实现该模式。

### 2.2 首次与再次访问

- 未登录且本机尚未确认欢迎页：根路径 `/` 显示欢迎页。
- 点击“开始使用”：记录本机已看欢迎页并进入 `/register`。
- 点击“已有账号，直接登录”：记录本机已看欢迎页并进入 `/login`。
- 未登录且本机已确认欢迎页：复用当前 `SmartEntry` 规则，有历史手机号时进入登录，否则进入注册。
- 已登录：直接进入 `/select-user`。
- 直接访问 `/login` 或 `/register` 始终可用，不强制绕回欢迎页。

本机标记仅用于减少重复展示，不属于认证或安全凭据；清理浏览器数据后重新展示是可接受行为。

### 2.3 视觉与移动端

- 使用用户提供的“星希望”母子星光路径竖版图作为主视觉。
- 生成 WebP 生产资源，目标不超过 500KB；保留足够清晰度，不把聊天临时路径写入代码。
- 图片使用 `cover` 填充，主体人物和标题在 375px 宽度下不可被关键裁切。
- 底部使用渐变遮罩承载一个主按钮和一个次按钮，不额外堆叠产品说明。
- 触控目标至少 44×44px，适配 `env(safe-area-inset-bottom)`，不依赖 hover。
- 网络慢或图片加载失败时仍显示“星希望”、一句简短说明和两个可操作按钮。
- 欢迎页、登录页和注册页新增文案全部进入 i18n。

## 4. 阿里云真实短信认证

### 4.1 接入方式

新增生产提供方 `aliyun-pnvs`，复用现有接口：

- `POST /api/auth/sms/send`
- `POST /api/auth/sms/login`
- `POST /api/auth/register`

服务端使用阿里云官方 Node.js SDK调用：

- `SendSmsVerifyCode`：系统生成 6 位数字验证码，有效期 300 秒，重复发送间隔 60 秒，覆盖上一条未使用验证码；
- `CheckSmsVerifyCode`：注册、短信登录或重置密码时由阿里云校验；
- 系统签名使用控制台已验证可送达的 `恒创联众`；
- 系统模板使用登录/注册模板 `100001`。

签名和模板作为生产环境配置，不硬编码在业务逻辑中。当前短信认证仅支持中国大陆手机号，前后端继续校验 `^1[3-9]\d{9}$`。

### 4.2 密钥与配置

生产服务器仅使用 RAM 子用户密钥，权限限定为：

- `dypns:SendSmsVerifyCode`
- `dypns:CheckSmsVerifyCode`

环境配置：

- `SMS_PROVIDER=aliyun-pnvs`
- `ALIBABA_CLOUD_ACCESS_KEY_ID`
- `ALIBABA_CLOUD_ACCESS_KEY_SECRET`
- `ALIYUN_PNVS_SIGN_NAME`
- `ALIYUN_PNVS_TEMPLATE_CODE`

密钥只写入服务器现有 `scripts/production_env.local.bat`，不得进入 Git、增量包、日志、API 响应或前端构建。部署脚本不得覆盖已存在的密钥；重新配置时必须明确提示。

### 4.3 频控与失败处理

- 单手机号同用途 60 秒内只能发送一次。
- 单手机号每小时最多 5 次、每天最多 10 次。
- 单 IP 每小时最多 30 次发送请求，防止批量盗刷；验证码校验与普通密码登录继续使用现有认证限流。
- 单个验证码最多校验 5 次，成功后立即失效。
- 前端点击发送后立即禁用并显示 60 秒倒计时，避免重复点击。
- 生产环境永不返回或展示 `devCode`。
- 阿里云超时或失败时返回明确的可重试提示，不先写“已发送”记录。
- 不启用短信状态报告回调；100 人内测可直接使用控制台发送记录排障，避免新增暂时不需要的公网回调面。

现有 `mock` 和 `http` 提供方保留用于本地测试和兼容；生产环境未配置真实提供方时，短信发送必须失败并返回 503，不得自动回退到 mock。

## 5. 数据与并发设计

当前 SQLite 已启用 WAL、`busy_timeout=30000`、`synchronous=NORMAL`、64MB 缓存和高频索引，适合约 100 名低到中等并发的家庭内测。账号总数不是瓶颈，集中写入才是主要风险。

本阶段保持单进程 Node.js + SQLite，不引入 PostgreSQL 或分布式队列。原因是 100 人内测不足以证明迁移数据库的必要性，现有架构更容易备份和回滚。

短信审计继续复用 `auth_sms_codes`：

- 保存手机号、用途、提供方、发送流水标识、创建/失效/消费时间和尝试次数；
- 阿里云负责验证码生成与真实性校验，数据库不保存明文验证码；
- 新字段只能通过幂等追加迁移加入；
- 保持 `(phone, purpose, consumedAt, expiresAt)` 查询索引；
- 发送成功后再写审计记录，校验成功后原子标记已消费。

若压测出现写锁，不通过缩短安全等待或忽略异常掩盖问题；先检查长事务和缺失索引。只有持续出现超过 50 个并发写入、数据库文件明显增长或 p95 写入长期超过 500ms 时，才另立阶段评估 PostgreSQL。

## 6. 百人内测容量验证

容量结论必须来自本机或服务器同配置验证，不直接向真实短信接口压测。

### 6.1 数据与场景

- 使用独立测试数据库或临时数据库副本结构，绝不对生产 `stellar.db` 写压测数据。
- 建立 100 个测试家长账号与最小家庭数据。
- 使用 mock 短信提供方验证注册业务路径，真实阿里云仅做 1–2 个受控人工端到端号码验证。
- 20 个并发客户端持续 5 分钟，混合执行登录、家庭读取、任务列表读取、少量任务写入和验证码业务状态写入。
- 追加一次 100 客户端同时读取的短时峰值测试。

### 6.2 验收门槛

- API 进程无崩溃、无未处理 Promise、无 `SQLITE_BUSY`。
- 非故意限流请求无 5xx；认证和限流返回符合预期状态码。
- 读请求 p95 小于 500ms，普通写请求 p95 小于 800ms。
- 注册手机号唯一性成立，无重复家庭、无半注册账号。
- 压测结束后 `PRAGMA integrity_check` 返回 `ok`。
- 备份脚本可执行，部署验证脚本通过。

如果服务器硬件或后台进程导致门槛未通过，发布结论必须写明实际并发上限和瓶颈，不宣称支持 100 人同时在线。目标是支持约 100 名测试用户，而不是 100 名用户同一秒集中提交写操作。

## 7. 代码边界

- 欢迎页作为独立懒加载页面接入现有 `App.tsx`，不重写认证上下文。
- 短信提供方从 `server.ts` 涉及区域拆到一个独立模块；已有 API URL 和响应结构保持兼容。
- 复用现有 `auth_sms_codes`、验证码页面和认证流程，不新增邀请码表或管理后台。
- 只调整本阶段涉及的品牌文案，不顺带重构登录/注册页面的其他交互。
- 不修改奖励、任务、探索、审批、数据库业务数据或经济规则。

## 8. 测试与验收

### 后端

- 阿里云发送参数、成功响应、超时、拒绝和配置缺失均有可运行测试。
- 阿里云校验仅接受 `PASS`，错误码和异常不得误登录。
- 生产环境不返回 `devCode`。
- 手机号、IP、小时/每日限流和 5 次校验上限可验证。
- 并发注册同一手机号只能成功一个。
- 现有密码登录、mock 短信、本地构建和全部后端回归继续通过。

### 前端

- 375px 下欢迎页无横向溢出，按钮、图片回退和 iOS 安全区域可用。
- 首次访问展示欢迎页；点击后正确分流；再次访问不重复阻塞。
- 已登录用户不看到欢迎页。
- 注册、短信登录、密码登录和错误提示均可操作。
- HTML、PWA、欢迎页和认证页显示“星希望”，无主要用户界面残留“星辰早晨”。

### 生产检查

- `http://starcoin.h5-online.com/` 跳转 HTTPS，HTTPS 返回 200。
- 真实手机号能收到验证码并完成一次新注册和一次短信登录。
- 密钥不存在于 Git diff、构建产物、增量包和日志。
- 后端测试与构建、前端生产构建、Playwright 375px smoke、生产页面白屏检查、容量验证和部署 `ValidateOnly` 全部通过。
