# Phase 5A 孩子端“今天”行动闭环设计规格

**状态：** 已按用户批准方向锁定
**范围：** `/child/today`、`/child/challenge`、孩子端任务数据刷新与 375px 回归测试

## 1. 目标

孩子在“今天”页面先看懂任务，再明确选择开始；进入挑战中心后必须定位到同一个任务，返回“今天”后必须看到最新状态。页面继续遵守一次只突出一个主行动的原则，不恢复旧版高密度任务列表。

## 2. 交互合同

1. “今天”主任务卡显示任务名、完成方式、目标、预计时间、金币、成长经验和确实存在的游戏票预告。
2. 点击主任务或“稍后再做”任务只打开当前页详情抽屉，不立即离开页面。
3. 详情抽屉中的“开始挑战”或“继续计时”进入：
   `/child/challenge?tab=<today|family>&taskId=<id>&from=today`。
4. 挑战页只从当前孩子最新的 `/child/dashboard` 任务集合中寻找 `taskId`：
   - 可开始任务：切换到正确分类、展开列表、滚动并高亮该卡片，同时打开任务详情。
   - 进行中任务：切换、滚动并高亮后直接恢复计时抽屉。
   - 不存在、已完成、过期或非法任务：不打开任何其他任务，显示明确提示并清理无效参数。
5. 从定向挑战进入时显示“返回今天”入口；返回后“今天”调用布局提供的 `refresh()`，重新读取任务、余额和审核状态。
6. 页面重新获得焦点或从后台回到前台时再次刷新；请求失败保留旧内容并提示可下拉重试，不白屏。

## 3. 数据与安全

- 不新增 API，不修改任务状态机，不修改 SQLite。
- `taskId` 只作为前端定位提示，不能触发越权读取；最终只接受当前 `/child/dashboard` 返回的任务。
- 金币使用 `coinReward`，成长经验使用 `xpReward`，不得与 `rewardXpTotal` 混用。
- 游戏票只展示后端已经返回的 `gameTicketPreviewMinutes` 或 `gameTicketEarnBySpeed`。
- 早餐保持独立入口，不伪装成普通任务。

## 4. 移动端与国际化

- 375px 无水平溢出，任务名允许两行。
- 所有新触控目标至少 44×44px。
- 抽屉复用 `BottomSheet` 的滚动和安全区能力。
- 新增可见字符串全部通过 `t('...')` 获取。

## 5. 验收标准

1. 点击“今天”任务不会立刻跳页，而是出现包含完成目标与全部已知奖励的详情。
2. 从详情开始后 URL 含同一任务 ID，挑战页自动打开同一任务，不会落到默认第一项。
3. 进行中的任务直接恢复对应计时器。
4. 无效任务 ID 不打开其他任务，出现可理解提示且页面仍可操作。
5. 点击“返回今天”后至少重新请求一次 `/api/child/dashboard` 并展示新状态。
6. 375px Playwright 覆盖详情、定向进入、返回刷新和非法 ID；前端构建零错误。

## 6. 非目标

- 不改变任务审核、奖励结算、宝箱或计时算法。
- 不增加新的任务类型、奖励类型或一级导航。
- 不重构 1800 行挑战页中与本闭环无关的学习、宝箱和低电量逻辑。
