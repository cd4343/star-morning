# Phase 12 家长探索规划器与可信信源系统设计规格

**状态：** 已按 2026-07-17 用户确认的方案 C 锁定，等待书面复核

**范围：** 家长端探索发现流程、系统级信源库、检索核验、结果排序、来源运维与相关移动端回归

**边界：** 探索仍不是任务或奖励系统，不获取实时定位，不编造地点、图片、说明、价格、日期或适龄信息

## 1. 背景与冲突处理

当前 `/parent/explore` 将发现、地点搜索、关注源维护、链接预览和长表单编辑同时交给家长。`ParentExplore.tsx` 已约 1498 行；后端发现逻辑主要集中在约 1313 行的 `exploreFeed.ts`。现有生成器只按单个轮换关键词搜索高德，并读取每个家庭自行添加的关注源，不具备系统级信源健康、字段证据、分级时效或规划请求检索。

`2026-07-14-phase5-parent-explore-workbench-design.md` 曾把“新推荐算法”列为非目标。本规格来自更新且更明确的用户需求，仅覆盖该项旧边界；Phase 5 的发现—计划—记录结构、家庭隔离和不使用实时定位等规则继续有效。

## 2. 产品目标

家长只负责表达家庭真实约束和做最终选择，系统负责资料查找、结构化、核验与整理：

1. 家长在约 20 秒内完成一次探索规划，不再填写名称、图片、介绍、地址和活动详情长表单。
2. 支持快捷选项，也支持输入一句自然语言、具体地点名称或官方活动链接。
3. 每个展示结果都必须有可追溯来源、通过完整度门禁，并处于对应字段的有效期内。
4. 可靠结果不足时诚实显示 1–2 个并提供一键调整，不为了凑满 3 个降低真实性门槛。
5. 信源选择、健康检查、冲突处理和更新节奏由后端承担；家长端只看到简洁的可信提示。

## 3. 家长端流程

### 3.1 第一屏：快速规划卡

探索页默认进入“发现”，显示一张移动端快速规划卡：

- **自定义想法（选填）：** 支持自然语言、具体地点名称和公开活动链接。
- **孩子最近想体验：** 自动带入孩子最近选择的最多两项体验，家长可调整但不覆盖孩子保存的原始意向。
- **什么时候去：** 今天、这个周末、下周、自选日期。
- **这次想获得什么：** 放电、增长见识、动手体验、亲子陪伴等成人目标。
- **现实条件：** 城市、区域范围、预算、室内外偏好。
- **主操作：** “查找可靠方案”。同一屏只保留这一个视觉最强操作。

没有家庭出发点时，界面不得承诺“车程 30 分钟”。第一版使用“指定城区 / 全市 / 周边城市”范围。只有未来由家长主动保存近似出发点并接入路线接口后，才显示真实路线时间；不申请 GPS。

### 3.2 自定义文字的透明解析

自定义文字不直接生成地点内容，只生成检索意图。系统把解析结果分成三组并让家长看见：

1. **可核验硬条件：** 城市、日期、最高预算、明确地点、室内外（仅在来源可验证时生效）。
2. **检索与排序偏好：** 主题、体验方式、成人目标、区域偏好。
3. **暂不可可靠核验：** 实时拥挤度、精确车程、未接入数据源的交通便利度等；明确提示不会作为已验证条件。

首版使用确定性规则解析日期、金额、区域、体验词和 URL，不新增 AI 服务。无法归类的原文保留为搜索关键词，不静默丢弃。家长修改标签后，标签值优先于原文解析。

### 3.3 结果页

结果页最多展示一个主推荐和两个备选，并允许只返回 1–2 个。每张卡必须显示：

- 真实名称与有效图片；
- 长期地点或限时活动标识；
- 已核验的地址/场馆，活动还必须有有效日期；
- 价格仅在可靠来源提供时展示；设置预算后，未知价格的结果不通过预算硬过滤；
- 与孩子意向和本次成人目标的匹配原因；
- 简洁可信提示，例如“官方信息 · 今日核验”或“高德地点 · 近日更新”；
- “加入家庭计划”主操作和“推荐给孩子看看”次操作。

搜索结果默认仅家长可见。家长明确加入计划或推荐后才写入现有计划/发现流程，不能自动推送给孩子。

### 3.4 降低家长维护成本

- 系统信源管理从家长设置中移除。
- 现有家庭关注源和长表单不删除，收进“高级设置 / 我的关注源 / 手动补充”，保证旧功能和数据可用。
- 粘贴链接的默认流程改为“预览 → 核验结果 → 加入计划或推荐”；只有自动补全失败时才展开缺失字段，不默认展示全部字段。

## 4. 后端检索架构

新增独立 `exploreDiscovery` 业务模块，避免继续扩大 `server.ts` 和 `exploreFeed.ts`。现有路由 URL 保持不变，新路由使用 kebab-case：

- `POST /api/parent/explore/discovery/preview-intent`：解析并返回可修改条件，不保存原始文字。
- `POST /api/parent/explore/discovery/search`：执行可信检索并返回推荐、已应用条件、未支持条件和可选调整。

检索流水线固定为：

1. 校验 JWT、家庭、孩子归属和请求长度。
2. 解析自定义文字，并与快捷选项合并。
3. 根据体验词库和原始关键词生成最多 4 组查询，避免无限扩张请求。
4. 并行召回近期已核验活动、系统信源缓存、高德 POI 和该家庭已有可信关注源。
5. 按高德 ID、标准化名称与区域、坐标邻近关系去重。
6. 对候选前列做补全和字段级核验。
7. 通过真实性、完整度、时效和硬条件门禁。
8. 使用确定性整数评分排序，并保证长期地点与限时活动在有可靠候选时尽量混合。

评分只决定可靠候选的顺序，不得抵消门禁。建议权重为：孩子体验匹配 40、成人目标匹配 20、日期可用 15、预算匹配 10、区域偏好 10、来源新鲜度 5。

## 5. 分层信源库

### 5.1 信源等级与字段权威

- **S 级：** 官方主办方、场馆、政务文旅页面。活动日期、报名、票价、临时变更以此为准。
- **A 级：** 高德 POI。地点名称、地址、坐标、类别和可用图片以此为主要来源。
- **B 级：** 经审核的本地活动平台。只负责发现候选；日期、票价等关键字段必须回到 S 级来源核验。
- **家庭级：** 家长上传或现有家庭关注源。只在本家庭使用，不自动提升为系统信源。

交叉验证采用“字段权威”而不是简单数来源。一个可访问的官方页面足以确认其活动日期；高德和官方页面地址冲突时，地点坐标优先高德，活动举办场馆优先主办方。相同等级来源冲突且无法解释时，候选进入后台待核验，不展示。

### 5.2 系统维护方式

系统信源清单由版本化可信目录提供，并幂等同步到数据库。家长不维护该目录。第一版复用高德和现有官方/家庭源能力，不引入不明搜索图片或任意全网抓取。

可信目录不会自动收录陌生域名。每周覆盖率报告只提出缺口，运营者核验网站归属、字段能力和抓取稳定性后，才通过代码目录和下一次 code-only 增量包新增信源。尚未配置城市官方源时，系统仍可返回已核验高德长期地点和该家庭已有可信来源，但必须如实说明没有可靠的近期活动结果。

- **请求时：** 对最终候选重新检查来源可访问性、日期和关键冲突。
- **每 6 小时：** 刷新限时活动与报名状态。
- **每 24 小时：** 刷新营业状态、开放时间和可核验价格，并执行信源健康抽查。
- **每 30 天：** 重新核验稳定 POI 的名称、地址、坐标和类别。
- **每周：** 生成覆盖率报告，列出经常无结果的城市/体验分类、失效信源和结构变化；运营者只据此增加、修复或停用具体信源，不全量重做信源库。

连续三次抓取失败的信源自动降级，不再参与推荐，待后续健康检查成功后恢复。

## 6. 数据模型与迁移

所有迁移幂等、只增不删，不替换 `stellar.db`：

1. 新建 `explore_source_registry`：保存系统信源标识、类型、等级、城市/分类覆盖、字段权威、刷新间隔、启用状态和健康信息。
2. 新建 `explore_feed_item_evidence`：按推荐条目保存来源 URL、支持字段、内容哈希、核验时间、过期时间和证据状态。
3. 新建 `explore_discovery_runs`：只保存城市、规范化体验键、目标、结果数量和失败代码，用于覆盖率报告；不保存家长原始文字、孩子姓名或地点自由文本，90 天后清理。
4. 为 `explore_feed_items` 追加 `verified_at`、`fresh_until`、`verification_level`，便于查询门禁；API 输出映射为 camelCase。

现有 `explore_feed_sources`、`explore_feed_items` 和历史推荐保持原样。旧完整卡不会自动获得“近期已核验”标签，只有重新核验成功后才能进入新规划器结果。

## 7. 真实性与时效门禁

任何推荐必须同时满足：

- 非占位名称；
- 真实图片来自高德、官方页面或家长上传，并已下载校验 MIME 与大小；
- 有内容说明；
- 地点有地址/坐标，活动有场馆与未过期日期；
- 至少一条字段证据可访问；
- `fresh_until` 未过期；
- 不存在未解决的关键字段冲突；
- 满足城市、日期、年龄和家长明确设置的预算等硬条件。

内容说明只能摘取和压缩来源事实，不补写来源没有的信息。推荐理由可以根据孩子意向生成，但必须使用“适合原因”措辞，不能伪装成场馆事实。

## 8. 无结果与服务失败

后端可以自动扩展同义词、体验关键词和同类 POI；不能自动放宽城市、日期、预算等硬条件。若可靠活动不足，可返回相关的已核验长期地点并明确标识，不声称存在活动。

仍无结果时，前端显示“当前条件下没有足够可靠的信息”，并提供单独的一键操作：调整日期、扩大区域或放宽预算。服务超时最多等待 12 秒；超时后返回已完成核验的部分结果和明确状态，不用假空态掩盖错误。

## 9. 安全、隐私与兼容

- 复用现有公开网络 URL/私网地址拦截、下载大小和 MIME 校验，防止 SSRF 与恶意图片。
- 原始自定义文字只在本次请求中使用，不进入运营日志或覆盖率表。
- 所有读写继续按 parent JWT 和 `familyId` 隔离。
- 不申请 GPS，不跟踪轨迹，不新增支付、导航、实时人流或路线时间能力。
- 保留现有 API URL、计划、打卡、媒体、孩子意向和历史发现数据。
- 新增用户可见文案全部进入 i18n。

## 10. 前端代码边界

只拆当前改动涉及的发现区域：

- `ParentExplore.tsx` 保留页面导航与现有计划/记录装配。
- 新增发现视图、规划表单、推荐结果和数据 Hook，各文件单一职责。
- 现有计划、记录、打卡确认、媒体与统计功能不重构。
- 375px 无横向溢出，所有触控目标至少 44px，不依赖 hover，底部操作适配 iOS 安全区。

视觉方向延续家庭成长系统的温和、清晰和可信感；不使用与现有产品脱节的独立设计系统。规划器以信息层级和快速选择为重点，不增加装饰性动画。

## 11. 测试与验收

### 后端

- 自定义文字解析可识别日期、预算、明确地点和 URL，并保留未知关键词。
- 无法核验的拥挤度或精确车程不得进入硬过滤或结果事实。
- 来源等级与字段权威冲突处理稳定，相同等级关键冲突会阻止展示。
- 过期证据、失效活动、缺图、缺说明和无地点/活动信息的候选不得返回。
- 同一 POI 的多来源候选只返回一次。
- 硬条件不足时不自动放宽；可靠结果为 1–2 个时如实返回。
- 覆盖率记录不包含原始文字，并按 90 天清理。
- 跨家庭访问、私网 URL 和非法图片继续被拒绝。

### 前端

- 375px 下可完成快捷选择、自定义解析、条件修改、搜索和加入计划。
- 自定义文字解析失败时保留原文并允许重试或改用快捷选项。
- 结果卡显示来源时效；无结果和部分结果均有明确下一步。
- 系统信源维护不出现在家长常规设置；旧家庭关注源仍可从高级设置访问。
- 现有发现、计划、记录、打卡确认、媒体、统计和孩子探索流程 smoke test 继续通过。

### 发布

- 后端测试、TypeScript 构建、前端生产构建、375px Playwright、生产全页面白屏检查和部署验证全部通过。
- 数据库迁移前自动备份；每个子阶段独立提交、可独立回滚。
- 不在增量包中携带 `stellar.db`、`node_modules`、历史临时包或本地环境文件。
- 最终生成一个 Phase 12 累计增量包，`LATEST_PATCH_PATH.txt` 只指向最新包；验证后同步当前 GitHub 分支。

## 12. 实施分段

1. **Phase 12A：** 数据迁移、信源注册、证据与时效门禁、检索/解析接口及后端测试。
2. **Phase 12B：** 家长快速规划卡、结果页、链接简化流程、i18n 与 375px 回归。
3. **Phase 12C：** 调度刷新、信源健康、覆盖率报告、旧关注源高级入口及生产验证。

## 13. 非目标

- 不接入来源不明的图片搜索或任意全网抓取。
- 不使用 AI 生成地点、活动或来源缺失的字段。
- 不保证每次都有 3 个结果。
- 不实现实时拥挤度、精确路线时间、导航、购票或自动报名。
- 不新建管理员后台；系统可信目录先随代码版本维护，待实际运营量证明需要后再评估独立后台。
- 不调整探索以外的任务、金币、经验、权益、宝箱或抽奖规则。
