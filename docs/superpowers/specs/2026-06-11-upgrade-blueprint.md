## 1. 经济参数自动建议（"建议定价"系统）

**原则**：确定性公式 + 家长确认制，系统永不自动改价（Rule 5）。

**锚点制设计**——家长在引导时只回答三个问题，系统推导全部定价：
1. 孩子每天大概能完成几个任务？（→ 日均收入预期）
2. 你希望孩子攒多少天能换到一个中等奖品？（→ 商品定价锚）
3. 一次 30 分钟游戏时间在你家"值"多少？（→ 特权定价锚）

**任务建议价** = 基准(10分钟=10金币) × 时长系数(√(分钟/10)) × 抗拒系数(轻松0.8 / 普通1.0 / 勇气1.3)。`taskRewards.ts 的 getTaskRewardSuggestion` 已有雏形——改造点是**浮出**：创建任务时默认填入建议值，旁边一句"为什么是这个数"（10分钟普通任务≈10金币）。

**商品建议价** = 期望周期(天) × 孩子近14天日均净收入（实测，不是理论值）。创建商品时显示："按最近的收入，小明大约 X 天能换到它"+ 周期滑杆(3天/1周/2周/1月)反推价格。特权同理（privilege-pricing 接口已有，挪到创建流程里）。

**再平衡信号**（进周报）：金币结余两周增长 >50% → "奖品可能太贵或太少了"；任务完成率 <40% → "定价或难度可能偏高"。只提示，家长点确认才生效。

## 2. 等级体系与双货币厘清

**概念一句话化**（UI 各处用同一套说明）：
- 🪙 金币 = 零花钱（赚来花掉）
- ⭐ 经验 = 成长刻度（只涨不花，代表"我走了多远"）
- 👑 特权点 = 信任额度（审核通过的努力累计转化，兑换"权利"）

**等级的好处 = 自主权放权**（不发钱，防通胀，且正中 ADHD 自主性培养）：
| 等级 | 解锁 |
|---|---|
| 每级 | 新称号 + 头像光环（纯荣誉，配升级庆祝动画） |
| Lv3 | 背包物品转赠权 |
| Lv5 | 抽奖资格（现在人人可抽，改为低等级引导先攒钱目标） |
| Lv8 | 自选头像/主题色 |
| Lv10 | 「自主任务」：孩子自己提任务给家长批准 |
| Lv15 | 周末自主计划权（自己排周末任务顺序） |
设计含义：等级越高，系统（和爸爸）越信任你自己管自己——这是把"自驱"写进机制。落地：等级权益表入库（level_perks），前端按等级显隐入口，升级时全屏庆祝展示"你解锁了什么"。

## 3. 家长端信息架构重构

**三层结构**取代现在的单页堆叠：
- **「今天」**：收件箱。待审核任务、待确认探索、待审资讯、异常提醒（连续2天没活动等），自上而下处理完即清空。这是家长 90% 的日常。
- **「孩子」**：按孩子维度的状态页。顶部本周叙事卡（周报），下面趋势图表（现 Dashboard 的统计区搬来），多孩时横向切换。
- **「管理」**：任务/商品/成就/惩罚/探索/家庭 的配置入口列表（低频操作收纳）。
底部导航：今天 / 孩子 / 管理 / 我。

**迁移策略**（不大改版）：第一步把"收件箱"做成组件置顶现有 Dashboard；第二步新建三个路由页逐块搬迁；第三步 Dashboard 退役。每步可独立上线回滚。

## 4. 品牌与吉祥物（电子宠物）

**品牌**：保留「星辰早晨 / StarMorning」——名字自带故事（每个早晨的一颗星），识别物锁定"星星"。先做三件套：主色体系（星空蓝紫 #4F46E5 系 + 晨光橙黄 #F59E0B 系，现有 UI 已接近）、统一圆角/字号规范（design tokens 落成 CSS 变量）、Logo（星+晨光的简单图形）。

**吉祥物「小晨星」**——一颗有表情的小星星。**关键设计决策：做"伙伴"，不做"宠物责任"**。不做喂养/饥饿/死亡机制——那会给 ADHD 孩子新增愧疚源（漏一天宠物饿了=又一个失败）。小晨星只反映和陪伴：
- 连续完成任务 → 越来越亮，长出光环
- 孩子进冷静站 → 它陪着一起呼吸（动画同步）
- 升级 → 它先欢呼
- 空状态/加载 → 它的各种小表情替代现在的 emoji
落地路径：5 个基础表情 SVG（平静/开心/打气/睡觉/庆祝）→ 接入空状态、庆祝、冷静三个场景 → 后续动效。我可以直接生成 SVG 初稿供你筛选。

## 5. ADHD 特化 backlog（讨论稿，逐条可单独做）

1. **专注可视化卡**（孩子端"我的"）：本周专注总分钟、最长一次、对比上周——"看见自己的专注力在长大"
2. **低电量模式**：孩子或家长一键开启"今天不太行"→ 全局只显示 1 个最小任务 + 冷静站入口，其他全部隐藏；不扣任何东西，明天自动恢复
3. **身体启动**：点开始后 10 秒呼吸/伸展引导动画再进计时（启动仪式降低启动阻力）
4. **时间侦探**：提交时让孩子猜"我用了多久"，猜中±20% 给经验——时间感知训练游戏化（ADHD 核心缺陷之一）
5. **过渡软提醒**：计时剩 2 分钟时温和提示音（避免戛然而止的转换冲击）
6. **感官设置**：声音/震动/动效强度三档，孩子自己调
7. **周节律视图**（家长）：一周热力图显示哪些时段完成率高 → 把难任务安排在孩子的高能时段

## 6. 周报（确定性规则拼装，不用 AI）

- 每周日 20:00 生成（复用 feed 调度器模式），存 weekly_reports 表
- **孩子版**：成长故事卡——"这周你主动开始了 5 次任务，勇气关过了 1 次，比上周多走了 2 步 ⭐"（模板 + 数字填充，语气只比较自己）
- **家长版**：3 个关键数（完成率/主动启动次数/情绪求助次数）+ 1 段叙事 + 1 条建议（再平衡信号见第 1 节）
- 入口：家长端「孩子」页顶部；孩子端周一首次打开弹卡

## 7. 成长档案

数据已齐（任务/成就/探索/照片/周报），按学期/年聚合的只读页面 + 月度高光（自动选：最难任务、第一次尝试、最佳照片、家长最暖回应）。远期导出 PDF。**架构影响小**：新表 + 聚合查询，不动核心，无需为它重构。

## 8. 性能与架构演进（"卡"的体检和处方）

**已做**（本批）：Express gzip、静态服务器 gzip、审批节流。预计首屏传输量降 60-70%。

**短期处方**（部署级，1 周内）：
1. **Nginx 取代 Python 静态服务器**（Windows 版 nginx 即可）：静态文件性能、HTTP/1.1 keep-alive、反代 /api 到 3001 端口——顺带解决 CORS 和移动端化的域名问题。我可以出完整 nginx.conf
2. **Dashboard 查询并行化**：家长/孩子 dashboard 现在十几个查询串行执行，改 Promise.all 并行 + 合并同表查询，预计响应时间砍半
3. **确认服务器规格与带宽**：你 RDP 进去看下 CPU/内存/带宽（阿里云控制台），1M 带宽是"打开慢"最常见元凶——gzip 后会明显缓解，但带宽 <3M 建议升
4. 探索图片出缩略图（现在列表直出原图）

**中期**：只读统计接口 60 秒内存缓存；首页接口瘦身（dashboard 拆"首屏必须"和"懒加载"两个接口）。

**长期（多家庭）**：SQLite 在单服务器支撑几百家庭没问题（每家庭数据量小、事务已串行化）；超过 ~500 家庭或写并发明显时再评估 PostgreSQL。**服务不必拆微服务**——单体 + 清晰模块边界足够到几千家庭规模。

## 9. 整体重构评估（重要结论：不要大爆炸重写）

你提的"全新梳理、可能重构"，我的专业意见是：**渐进绞杀，不推倒重来**。理由：核心业务逻辑（经济/审核/抽奖/惩罚）刚刚完成加固并有 32 项测试守护，重写等于把这些风险再经历一遍；而你的痛点（卡、乱、难维护）靠模块化拆分就能解决。

**六步绞杀计划**（每步独立上线，验收=测试全绿+性能不退）：
1. server.ts 抽 auth 模块（authRoutes.ts）——已有 exploreFeed.ts 示范模式
2. 抽 tasks + review 模块（最大块，带上单元测试）
3. 抽 shop/inventory/lottery（rewardSystem.ts 已独立，归并整理）
4. 前端家长端按"三层 IA"分页（同时完成第 3 节）
5. 前端巨页拆组件（ChildWishes/ChildChallenge 按 Tab 拆）
6. dashboard 接口拆分 + 缓存层
全程 server.ts 从 7500 行降到 <1500 行（只剩装配），新功能（周报/等级权益/成长档案）全部直接写在新结构里。
