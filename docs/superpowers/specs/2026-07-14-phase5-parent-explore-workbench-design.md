# Phase 5B 家长端探索行动工作台设计规格

**状态：** 已按用户批准的方案 B 锁定
**范围：** `/parent/explore` 信息架构、推荐筛选、计划与记录、375px 回归测试

## 1. 目标

把当前“地点、搜索、待确认、设置、回忆”五个平级工具重组为家长能顺着完成的“发现—计划—记录”工作台。探索继续用于发现真实世界、安排家庭活动和记录体验，不变成任务系统、金币系统或实时定位系统。

## 2. 工作台结构

页面顶部保留简短定位和三个可行动摘要：待确认打卡、计划去地点、最新孩子反馈。唯一主按钮是“找一个适合去的地方”。主导航只有：

- **发现：** 一键生成推荐、个性化筛选、具体地点搜索、手动添加。
- **计划：** 按“计划去、想去、已去过”组织地点，允许编辑、归档或删除。
- **记录：** 待确认打卡优先，可切换查看家庭回忆。

设置作为次级入口，不再占主流程导航。

## 3. 发现

1. 基础配置使用城市、孩子年龄、大致可用时间和兴趣分类。
2. 一键推荐真实复用现有接口：先保存城市、分类和每日条数，再调用幂等的 `POST /api/parent/explore/feed/generate-now`。
3. 年龄、时间与费用只筛选推荐条目中已有的结构化字段；字段缺失时保留条目并标记信息待核验，不制造虚假匹配。
4. `GET /api/parent/explore/feed-settings` 的待审核条目补充返回现有表中的适龄、活动日期、费用、预约、推荐理由和核验状态字段，不新增表或列。
5. 具体地点搜索继续使用高德文字搜索；服务未配置或搜索失败时保留输入并显示“手动添加”主替代路径。

## 4. 计划

- 复用 `explore_places.status` 的 `planned`、`wishlist`、`visited`。
- 地点卡显示两行标题、分类、状态、次数、地址或简介；不因为窄屏提前省略关键名称。
- 新建、编辑、删除和有打卡记录时归档的现有语义不变。
- 地图不成为家长端默认工作区；坐标补全留在次级设置。

## 5. 记录

- 未确认打卡排在已确认打卡之前。
- 文字回应、语音回应、媒体查看和批量确认继续复用现有接口。
- 家庭回忆作为记录内的二级视图，继续读取现有时间线。
- 确认失败保留家长输入和录音，不把失败伪装成成功。

## 6. 错误、安全与边界

- 初始地点或打卡请求失败时显示错误卡和重试按钮，不渲染假空状态。
- 所有写操作仍依赖家长 JWT、服务端家庭隔离和现有 MIME/配额校验。
- 不请求 GPS，不新增轨迹，不把地点或推荐自动转换成任务，不发金币。
- 不修改现有 API URL；只扩充同一家庭可见的待审核响应字段。

## 7. 移动端与国际化

- 375px 无水平溢出；三个阶段按钮和次级设置入口均达到 44px。
- 每个视图只保留一个视觉最强的主行动。
- 新增工作台、筛选、错误和空状态字符串全部进入 `zh-CN` i18n 字典。

## 8. 验收标准

1. 首屏不再出现五个同权标签，而是“发现—计划—记录”和次级设置。
2. 首屏可看见待确认、计划地点和最近反馈摘要，主按钮进入发现。
3. 家长可一键保存推荐偏好并生成推荐；结构化条目可按年龄、时间、兴趣筛选。
4. 高德未配置时仍可手动添加地点，表单和筛选值不丢失。
5. 计划页按状态组织地点；记录页先显示待确认并可进入回忆。
6. 初始 API 失败有明确重试；375px Playwright 覆盖三阶段、筛选、替代路径和确认入口。
7. 后端测试、前端构建、smoke 与生产全页面检查通过。

## 9. 非目标

- 不创建日历、路线规划、支付、导航或实时位置能力。
- 不建立新的 POI 推荐算法或 AI 推荐服务。
- 不全面重构探索后端和 1300 行页面的未触及业务函数。
