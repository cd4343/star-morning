# Phase 7：孩子端“今天”任务优先双 Tab 设计

## 1. 目标

孩子进入“今天”后首先看见家长为当天安排的完整任务，不因专注设计被静默截断；同时保留早餐小厨房，并允许在同一页面通过 Tab 往返切换。

## 2. 范围

本阶段只调整孩子端“今天”与“早餐小厨房”的页面组织和交互，不修改任务、早餐、奖励接口，不修改数据库，不改变家长端任务配置规则。

## 3. 页面结构

- 每次进入 `/child/today` 默认打开“今日任务”Tab，不记忆上次停留的早餐 Tab。
- 顶部使用两个至少 44px 高的等宽 Tab：“今日任务 N”和“早餐小厨房”。
- 删除“今天只做眼前这一步”“现在做什么”“建议现在开始”等主推荐区域。
- 删除单独的早餐入口卡片，避免出现进入早餐后没有同级返回入口的问题。
- 两个 Tab 共用孩子端现有账户头部和底部导航，不新增导航入口。

## 4. 今日任务 Tab

### 4.1 完整展示

- 展示后端当天返回的全部任务，不使用 `slice`、折叠或“稍后再做”数量上限。
- 任务按照可操作优先、审核中其次、已完成最后排序，但不因状态被过滤出“全部”视图。
- 每张卡片继续展示任务名称、图标、完成要求、金币、成长经验和当前状态。
- 点击任务卡片打开现有任务详情；开始或继续任务仍进入现有挑战计时流程。

### 4.2 状态筛选

任务标题下方提供四个可点击筛选项，并展示实时数量：

- 全部：默认状态，显示当天全部任务。
- 待完成：`todo`、`running`、空状态以及 `rejected`；被打回的任务仍显示“需修改”状态文案。
- 审核中：`pending`。
- 已完成：`approved`、`completed`。

筛选只影响当前列表，不跳转路由、不修改任务数据。切换到早餐再返回任务时重置为“全部”，防止孩子误以为任务消失。筛选结果为空时显示明确空状态。

## 5. 早餐小厨房 Tab

- 复用现有 `/child/morning` 数据与保存逻辑，但内容嵌入“今天”页面的早餐 Tab。
- 删除“今天早餐怎么搭”大幅渐变头图及说明文字。
- 首屏直接呈现日期选择、我的早餐组合、结算信息和保存按钮；可选早餐内容紧随其后。
- 早餐加载或保存失败时保留当前错误提示，不影响任务 Tab 使用。
- 旧 `/child/morning` 路由保留兼容，并重定向到 `/child/today?tab=breakfast`，避免旧入口失效。

## 6. 组件与数据边界

- `ChildToday` 负责 Tab、任务筛选和页面组合。
- 早餐内容从 `ChildMorning` 提取为单一可复用内容组件；不得复制 API 请求和保存逻辑。
- 任务数据继续来自 `ChildLayout` 的 `/child/dashboard` 响应。
- 早餐数据继续来自 `/child/morning` 和 `/child/breakfast-orders`。
- 用户可见新增文字必须使用 i18n key。

## 7. 移动端与可访问性

- 375px 宽度下可用，任务卡片不横向滚动。
- Tab、筛选项和任务卡片触控区域不小于 44px。
- 当前 Tab 和当前筛选除颜色外，还必须有文字或选中状态差异。
- 页面保留底部安全区，列表末项不被底部导航遮挡。

## 8. 验证标准

- 使用至少 6 个混合状态任务验证“全部”显示 6 个，无静默截断。
- 四个筛选的数量和卡片状态对应正确，切换早餐再返回后恢复“全部”。
- 早餐 Tab 可以选择日期、修改组合并保存；页面没有原大幅早餐头图。
- 旧 `/child/morning` 入口可进入早餐 Tab。
- 前端构建零错误，现有孩子端 smoke test 通过，并新增上述关键路径测试。
- 在 375px 和常用桌面宽度完成渲染检查，无白屏、遮挡和横向溢出。

## 9. 回滚

本阶段不涉及数据库。回滚只需恢复孩子端页面、早餐内容组件、路由、i18n 和对应测试文件。
