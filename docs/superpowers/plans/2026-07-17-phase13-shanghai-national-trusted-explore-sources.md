# Phase 13 上海与全国可信探索信源实施计划

**目标：** 保留上海专属深度信源，同时让家长在全国城市搜索时获得近期、真实、可追溯的地点或活动；来源不可用时允许少结果，不允许编造或用旧内容填充。

**实施边界：** 本阶段不改前端交互、不增加数据库破坏性迁移、不抓取小红书或大众点评作为事实来源。只有具备稳定结构并实际写好适配器的来源标记为“已自动接入”；其余官方/可靠平台仅进入受控目录，等待后续适配。

## 成功标准

- 上海搜索同时使用高德地点、上海博物馆活动和上海图书馆活动。
- 全国城市搜索同时使用高德地点和国家公共文化云近期活动。
- 所有活动必须有真实标题、图片、说明、场馆和有效日期；城市无法精确确认、已过期或字段不足的内容被拒绝。
- 国家公共文化云只作为 B 级发现来源，活动日期、价格等缺失字段不推断。
- 信源目录清楚区分“已自动接入”和“待适配”，并保留健康状态、刷新周期和来源网址。
- 单个信源失败不拖垮其他信源；有可靠结果时返回 `partial`，全部失败且无缓存时才返回不可用。

## 文件与任务

### 任务 1：建立可审计的上海与全国信源目录

- 修改 `backend/src/exploreSourceCatalog.ts`
  - 加入 4 个启用信源：高德、国家公共文化云、上海博物馆活动、上海图书馆活动。
  - 加入文化和旅游部全国联播、国家文物局博物馆名录、上海文旅及重点场馆等“待适配”来源，默认禁用，不参与自动推荐。
  - 健康检查按每个来源自己的 `refresh_minutes` 到期，不再固定 24 小时。
- 修改 `backend/src/exploreSourceCatalog.test.ts`
  - 验证目录幂等、运行健康字段不被覆盖、禁用来源不参与探测、不同刷新周期生效。
- 新增 `docs/EXPLORE_SOURCE_CATALOG.md`
  - 罗列范围、可信等级、自动接入状态、可验证字段和官方链接。

### 任务 2：实现三个真实活动适配器

- 新增 `backend/src/exploreOfficialSources.ts`
  - 国家公共文化云：调用公开结构化活动接口，只使用源字段，不生成介绍；城市必须从活动字段精确匹配。
  - 上海博物馆：解析官方预约页中的活动名称、日期、场馆、地点、年龄和图片。
  - 上海图书馆：解析官方活动页中的名称、日期、地点和图片。
  - 输出复用现有 `ExploreDiscoveryCandidate`；活动证据 6 小时有效。
- 新增 `backend/src/exploreOfficialSources.test.ts`
  - 使用固定 HTML/JSON 样本验证解析。
  - 覆盖过期内容、城市不明、无图片、无场馆、成人活动对儿童年龄筛选的拒绝路径。

### 任务 3：并入现有探索检索链路

- 修改 `backend/src/exploreDiscoveryRoutes.ts`
  - 默认检索并行执行高德和官方活动适配器。
  - 上海额外启用两个本地深度信源；其他城市使用全国公共文化云。
  - 保留现有去重、完整度、日期、年龄、预算、城市和图片缓存门槛。
  - 测试注入 `searchProvider` 时不访问公网，保证测试可重复。
- 修改 `backend/src/exploreDiscoveryRoutes.test.ts`
  - 验证官方与地点结果合并、单源失败时部分成功、重复活动去重。

## 验证与发布

1. `cd backend; npx vitest run src/exploreOfficialSources.test.ts src/exploreSourceCatalog.test.ts src/exploreDiscoveryRoutes.test.ts`
2. `cd backend; npm test -- --run`
3. `cd backend; npm run build`
4. `cd frontend; npm run build`
5. 生成新的 Phase 13 累计增量包；不携带 `stellar.db`、密钥、日志、上传内容或依赖目录。
6. 更新 `临时/LATEST_PATCH_PATH.txt`，只让服务器上传最新累计包。

## 回滚

恢复本阶段涉及的后端文件和文档即可。新增目录行是幂等配置数据，不删除历史业务数据；即使回滚代码，探索原有高德与本地缓存流程仍可继续运行。
